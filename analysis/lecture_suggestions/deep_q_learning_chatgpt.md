## 6.1 · From one transition to one DQN update

| Slide | Min | Teaching move and question |
| --- | ---: | --- |
| 1. Values from pixels | 4 | Open with the old Atari image. A single Breakout frame locates the ball. What input would help infer its direction? Show the stack of recent frames and the network’s output, one estimated value per discrete action. Have students point to the score used to act and the score fitted after observing a transition. |
| 2. Online Q-learning with shared weights | 5 | Start with the Week 5 approximate control update. An exploratory action supplies the transition. A greedy successor value supplies the bootstrap. Draw the network twice with the same weights and ask which prediction receives the gradient. Changing shared weights can also change tomorrow’s target for this very transition. |
| 3. Two problems in one stream | 4 | Show three successive near-identical frames, then revisit one stored transition after a weight update. The first picture motivates changing which examples reach the learner together. The second motivates controlling when the bootstrap changes. Students predict which problem survives shuffling. |
| 4. Replay | 6 | Append the new transition and its termination flag to a bounded store 𝒟, evict the oldest when full, then draw a uniform minibatch after warm-up. Draw one old and one recent row. Ask how one interaction can contribute to several updates, and why an action taken by an earlier behaviour policy is usable for Q-learning. Notes address temporal dependence, coverage and the mixture of past behaviour policies. |
| 5. A target that stays put between copies | 6 | Start with **w**⁻ ← **w**. Compute the bootstrap with the snapshot while fitting **w**. For one stored row, walk through two optimizer steps and a scheduled hard copy. Distinguish holding a label fixed during differentiation from keeping its generating weights fixed across updates. |
| 6. Assemble the loop | 6 | Build old slide 12 in three passes: collect and store, sample and construct targets, update and conditionally copy. For each row gather the online prediction at its recorded action. Use reward alone for a true terminal transition. Take one optimizer step on the batch mean half-squared error. Count hard copies in learner steps for this example. |
| 7. Choose the data | 4 | Give the buffer three cards: an older nonterminal row, an intervening row, and a newly appended terminal row. Reveal a possible uniform draw of the first and third. Ask which row came from the current environment step and which actions the loss will fit. |
| 8. Build the targets | 7 | In pairs complete the two rows below. Show the target-network outputs only after students have named the network and successor state they need. A terminal branch earns its reward with no next-action lookup. |
| 9. Take the parameter step | 8 | Calculate the batch loss and one actual parameter change below. Mark every object that changed, then perform the scheduled copy. Ask what would be different if the next copy were due three steps later. |
| 10. Reconstruct from memory | 5 | Give students an empty loop with slots for the stored action, the bootstrap, the optimizer and the copy direction. Ask which slots would change if the learner drew a different minibatch. Retain one completed copy of the loop for 6.2. |

**Worked trace for slides 7–9.** Use a finite episodic task with left and right actions and γ = 0.5. The draw below is specified so everyone can check the same update. Online and target weights have diverged since their last copy. Successor outputs are ordered (left, right).

| Sampled row | Recorded action | Reward | Online prediction at recorded action | Online outputs at successor | Target outputs at successor | DQN target |
| --- | --- | ---: | ---: | --- | --- | ---: |
| Older, nonterminal | left | 1 | 2 | (4, 2) | (2, 6) | 1 + 0.5 × 6 = 4 |
| Newly collected, terminal | right | −1 | 0 | — | — | −1 |

The target errors (target minus prediction) are +2 and −1. The mean half-squared error is (4 + 1)/4 = 1.25. For an inspectable component of the full gradient, take the additive bias of the left output head. Its derivative on the first selected prediction is 1 and on the second is 0. At step size 0.1, plain SGD increases this bias by 0.1 × (2 + 0)/2 = 0.1. The optimizer can also change shared features. The target weights stay fixed through this step and receive the updated online weights only if the copy is due. The buffer changes on collection. This arithmetic uses no optimizer internals beyond SGD.

## 6.2 · What does the maximum select, and what does an ablation show?

| Slide | Min | Teaching move and question |
| --- | ---: | --- |
| 11. Retrieve the nonterminal row | 4 | Hide its target. Ask which estimator picked right and which estimator supplied 6. Students often expect the mere presence of two networks to separate these jobs. Locate both operations in the DQN line. |
| 12. Take the maximum of noisy estimates | 7 | Start the **20-minute double-estimator activity**. Two successor actions both have true value zero. Give each an independent estimate of +1 or −1 with equal probability. Students enumerate four equiprobable pairs. The four maxima are −1, +1, +1, +1. Their mean is +0.5, although each action estimate has mean zero. Ask where this excess enters the preceding state’s target. |
| 13. Select with one table, evaluate with the other | 5 | Keep the same toy state. Students pick an action using the first table and read it in a fresh independent table. Its expected evaluation here is zero. Connect to the old two-branch MDP figure: optimism downstream can make an inferior branch attractive upstream. Explain tabular Double Q-learning’s two learned tables, choosing which to update on each transition, using that table to select and the other to evaluate, then reversing roles when the other is updated. Exposure-level explanation. |
| 14. Transfer to the networks already in the loop | 4 | Return to the exact row from slide 11. For Double DQN the online outputs (4, 2) pick left. The target network reads 2 for left, giving 1 + 0.5 × 2 = 2. DQN gave 4. The terminal target stays −1. Ask when the two methods agree, including immediately after a hard copy. |
| 15. Implement the patch | 4 | Finish the 20-minute activity. On nonterminal rows, replace the target-network maximum with a per-row online argmax and gather those columns from the target outputs. Keep targets detached. Students write this patch and check it on the two rows, expecting (2, −1). Collecting actions, replay, optimizer and the copy schedule carry over unchanged. |
| 16. Design the comparison | 6 | Full DQN is the reference. Cross uniform replay on/off with delayed target copies on/off. Define target off as a detached bootstrap from current online weights, and replay off as sampling the latest contiguous batch once ready. Match interactions, batch size, optimizer steps, exploration, architecture and evaluation schedule. The replay contrast bundles changes in temporal spacing, age and reuse. Ask what an observed score difference would establish. |
| 17. Read the Atari ablation | 8 | Start the **15-minute ablation activity** with the two rows below. In pairs compare one switch at a time. First hold fixed targets on and change replay, then hold replay on and change target use. Explain why comparing full DQN to the bare network answers a different question. |
| 18. Defend one diagnosis | 7 | Finish the ablation activity. Ask what the summary omits, what mechanism is plausible, and what observation could distinguish it. Have each pair propose a check using the same transitions or a matched rerun. Use the answer cues below. |
| 19. Inspect a learner | 6 | Two short debugging prompts. A fixed stored row’s plain-DQN label changes after every optimizer step between copies. Inspect the bootstrap weight source and target storage for accidental aliasing. A terminal row’s label varies with successor scores. Inspect the termination mask. Students name an observation that would verify each repair. |
| 20. Exit question | 4 | “After copying, DQN and Double DQN produce identical targets on my test batch. What batch would reveal whether I implemented the switch?” Answer: choose a nonterminal successor with disagreeing argmax actions and distinct target values at the two selected indices. Include a true terminal as a control. This rehearses the A2 check. |

**Interpretation for slides 12–15.** In the toy calculation, independence makes the second table’s noise average to zero conditional on the first table’s choice. In practical Double DQN the target is a delayed copy, so the estimators are related. In the notes distinguish reducing selection bias from guaranteeing unbiased targets or improved return. The example on slide 14 shows which number the algorithm computes. The repeated-noise calculation on slide 12 supplies the evidence for bias.

**Evidence for slides 17–18.** Historical game scores, transcribed from [CS234 lecture 4, p. 76](../../sources/stanford_cs234/lectures/lecture4post.pdf#page=76). Use the source’s four neural conditions. Slide 16 is a proposed classroom protocol. The source table alone does not establish that its experiments used every control in that protocol.

| Game | Deep network alone | Fixed targets only | Replay only | Replay + fixed targets |
| --- | ---: | ---: | ---: | ---: |
| Breakout | 3 | 10 | 241 | 317 |
| Seaquest | 275 | 1003 | 823 | 2894 |

With targets on, adding replay changes the Breakout score by +307 and the Seaquest score by +1891. With replay on, adding fixed targets changes them by +76 and +2071. Ask whether the same component has the larger conditional gain in both games. Compare within each game. Scores have different scales across games. The table supplies no per-seed spread or learning curves. For a follow-up, evaluate a fixed greedy policy snapshot on separate episodes at matched interaction counts, repeat across training seeds, and show per-seed returns and their spread. To investigate target motion, log the bootstrap on fixed nonterminal probe rows between copies. To investigate data reuse, log sample ages and per-transition draw counts. Neither final scores nor a low training loss identify a mechanism on their own.
